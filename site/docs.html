DEVELOPER GUIDE / V0.2

一个协议，多种决策方案。

Yuri 是面向星际争霸 II 的宏观决策实验平台。游戏提供结构化状态，策略选择动作，执行器将动作转为单位指令。

规则基线和交互沙盘已实现。Laya 接口与实验性游戏适配器已加入；真实权重推理、完整对局和胜率仍需实机验收。

项目架构

游戏观测 → Observation v1 → 策略 → Decision v1 → 游戏执行
                              ↓
                       JSON / JSONL 记录
                              ↓
                         官网可视化回放

新运行时位于 src/yuri_next。历史 TensorFlow / Keras 代码保留作参考，不会被新入口导入。Python 3.12、uv 和可选依赖分组替代旧环境。

LayaAPI 适配，待实战评估laya 0.3.21
行为克隆 / PPO后续扩展按策略添加

WSL 快速开始

在 Ubuntu 内执行，避免使用 Windows 的 Python 虚拟环境。

cd /home/tsonglew/yuri
uv sync --locked
uv run --locked pytest -q
uv run --locked yuri decide --policy rules \
  --state examples/observation.json \
  --output artifacts/rules.json

连接游戏还需要 SC2 与地图，安装 --extra game。WSL2 网络配置见 burnysc2 官方说明。

Laya 接入

uv sync --locked --extra laya
uv run --locked --extra laya yuri decide --policy laya \
  --state examples/observation.json \
  --budget-ms 120000 --output artifacts/laya.json

首次调用需要下载权重。策略把状态与合法动作送入 Router.predict，读取 choice 和 answer_confidence。加载失败、低置信度、非法动作或晚到结果会回退规则。

检查 executed_policy 确认实际策略。置信度不是游戏胜率。实时对局使用单任务后台推理，尚不提供原生计算的硬中断。

决策回放

回到决策实验室，导入导出的 JSON 或游戏产生的 JSONL。页面显示原始动作、置信度、延迟和回退原因，文件仅在浏览器本地读取。

回放冻结局面输入，异步记录地图展示执行时状态。官网不运行 Laya，也不会生成示例模型置信度。

策略扩展

实现 decide(Observation) → Decision 并注册工厂，同步更新 CLI、依赖分组和测试。执行器消费相同动作。

  1. 完善规则与敌军记忆，测出基线。
  2. 用同一组地图和对手比较 Laya。
  3. 积累轨迹，再加入行为克隆、PPO 或混合策略。

字段表、失败处理、升级矩阵、验收门槛和里程碑见完整开发文档。

发布官网

目标 tsonglew.github.io/yuri/。仓库 Settings → Pages 中选择 GitHub Actions；默认分支的 Pages 工作流构建发布，无需修改个人根站。

python3 scripts/build_site.py
python3 scripts/check_site.py
python3 -m http.server 8765 \
  --directory _site --bind 127.0.0.1

最终地址以工作流实际输出为准。模型、环境和对局日志不进入发布产物。
